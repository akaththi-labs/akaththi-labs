## Build for embedded systems from idea to production

Akaththi Labs is the open-source research arm of Akaththi Farms. We believe in building tools that work, sharing them openly, and fostering a community of developers who value quality and practicality.

<div class="feature-grid">
  <div class="feature-card">
    <h3>ESP-IDF Platform</h3>
    <p>Production-ready libraries for Espressif's IoT Development Framework. Field-tested sensor drivers, abstraction layers, and utilities for building reliable embedded systems.</p>
  </div>
  
  <div class="feature-card">
    <h3>FreeRTOS Integration</h3>
    <p>Real-time operating system components optimized for resource-constrained environments. Power-efficient task scheduling and sensor polling strategies.</p>
  </div>
  
  <div class="feature-card">
    <h3>Sensor Libraries</h3>

  <div class="feature-card">

## Contribution Workflow

We welcome contributions from the community. All projects follow standard open-source practices.

### How to Contribute

1. **Browse projects** — Check our repositories and open issues
2. **Discuss first** — For major changes, open an issue to discuss your approach
3. **Fork and branch** — Create a feature branch from main
4. **Write tests** — Include tests for new functionality
5. **Submit a PR** — Open a pull request with clear descriptions
6. **Code review** — Maintainers will review and provide feedback

### Contribution Guidelines

- Follow the coding style of the project
- Write clear, descriptive commit messages
- Add documentation for new features
- Ensure all tests pass before submitting
- Keep changes focused and atomic

### Code of Conduct

We are committed to providing a welcoming and inclusive environment. Be respectful, considerate, and professional in all interactions.

## GitHub-First Philosophy

Everything we build starts and lives on GitHub:

- **Version Control** — All code, documentation, and issues tracked in Git
- **Open Development** — Public repositories, transparent roadmaps
- **Community Review** — Pull requests reviewed by maintainers and community
- **Documentation** — README-driven development with clear examples
- **CI/CD** — Automated testing and validation via GitHub Actions

We believe in working in the open, learning together, and building tools that anyone can use, modify, and improve.
